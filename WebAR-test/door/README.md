# door — カメラAPI + マークアップだけで作るプリミティブなドア認識AR

**WebXR不使用・サーバーサイド不要・静的1ファイル。**
`getUserMedia` + `DeviceOrientation` + 素朴なエッジ検出(Sobel)だけで、
「ドアを認識 → 枠が光る → ボールが溢れて転がる」を実現するデモ。

スライドの主張「商用SDKや事前マッピングに頼らなくても、理論上はプリミティブな推論で
"ビタビタ" に近い表現はできるはず(できればマークアップで)」の実証実装。

## 構成

| レイヤ | 実装 |
|---|---|
| カメラ映像 | `getUserMedia` の `<video>` を `object-fit: cover` で背景に敷くだけ |
| 3Dシーン | **A-Frame のマークアップ**。ドア枠は `<a-box>` 3本 + `<a-plane>`(開口部)を HTML で宣言 |
| ドア認識 | Sobel縦エッジ → 列ヒストグラムのピーク対 → 上辺の横エッジ確認。約26行の「素朴な推論」 |
| 距離推定 | 「ドアの実寸は高さ2.0m」という仮定 + ピンホールカメラモデルで逆算 |
| 空間固定 | 検出時のカメラ姿勢でワールド座標に焼き付け、以後は DeviceOrientation(ジャイロ)で追従 |
| ボール物理 | 自前コンポーネント `ball-fountain`(重力・床バウンド・摩擦・転がり回転) |

## 体験の流れ

1. 「カメラを起動」→ カメラ / (iOSでは)DeviceOrientation の許可
2. ドア全体を画面に収める → 緑の矩形ガイドが出て、5回連続で安定検出されると確定
3. 検出できない環境では **画面のドアをタップ** → 2m先に固定配置(フォールバック)
4. 枠が3秒脈動 → 開口部が暗転 → ボールが溢れて床を転がる
5. 「再検出」でリセット

## 動作環境

- **iPhone Safari / Android Chrome の両方で動く**(WebXR不使用のため。ここが WebXR 版 `../webxr` との最大の違い)
- **secure context 必須**(getUserMediaの制約)。注意: `localhost` はOKだが、
  **スマホからLAN IP (`http://192.168.x.x:...`) で開くと `navigator.mediaDevices` がundefinedになる**

## 実機検証の3つの方法

```bash
# 1. 自己署名HTTPS (iPhone/Android両対応) — AR/ 直下のサーバーを使う
python3 ../serve.py     # → https://<LAN IP>:8443/door/ を開き、証明書警告を通す

# 2. Android限定: adbトンネル (証明書不要)
python3 -m http.server 8123 -d ..
adb reverse tcp:8123 tcp:8123   # スマホ側で http://localhost:8123/door/

# 3. デプロイ (本番): GitHub Pages / Netlify Drop に index.html を置くだけ
```

## このデモが示す限界 = スライドのネタ

これは意図的に「プリミティブ手法の到達点と限界」を見せる教材でもある:

- **トラッキングは3DoF**: DeviceOrientationは回転しか取れない。歩くとオブジェクトはついてこない(=生駒の鳥居で「QRで立ち位置を拘束した」のと同じ制約がそのまま残る)
- **距離はスケール仮定**: 「ドアは2mだろう」という事前知識が距離の唯一の根拠。単眼カメラ+幾何だけでは絶対スケールは原理的に決まらない
- **認識は寸法ヒューリスティック**: 縦長の強エッジ対をドアと呼んでいるだけ。本棚も窓もドアになる
- ここに **6DoF(SLAM)** を足したものが WebXR / ARCore、**事前マップとの照合** を足したものが VPS — という技術の階段が、このデモと `../webxr`(WebXR版)の比較で一望できる
